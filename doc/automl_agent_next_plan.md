## 3. 拟审批的行为约定

### 故障检测与早停

- **候选故障。** 训练损失、模型输出或验证目标出现 NaN/Inf 时终止该候选。仅在能够释放本次试验资源、设备仍可用时，将明确识别的 CUDA OOM 作为候选失败并继续搜索。记录原因码、异常类型、发生阶段、已用资源和是否继续。首版默认重试次数为 0，保持超参数与记录一致。
- **运行故障和预算停止。** 数据路径或格式错误、后端失效及分段执行路径中的未知异常终止运行并保留已有日志。全局截止、用户中断和单试验故障使用各自的原因码。批次间检查时间，验证结束后再确认结果是否在截止前完成。强制终止卡住的 CUDA 内核或整个进程留待进程隔离方案。
- **单试验早停。** 以完整内层验证的 `objective` 为准，目标值越低越好。热身后，连续 `patience` 次验证没有达到 `min_delta` 时停止。报告保留最佳有效验证值、最佳 epoch、实际完成轮数和停止原因。首版在固定预算调度中单独启用。Successive Halving 和 Hyperband 通过同轮排名淘汰候选，两条路径分别验收。

### 续训、排名与预算

- **分段执行。** 新协议接收候选 ID、累计目标 epoch、全局截止时间和上一阶段 checkpoint。返回实际完成 epoch、完整验证目标、终止原因及新 checkpoint 的引用。checkpoint 核对配置、数据划分、执行器及后端上下文，恢复模型参数与缓冲状态、优化器、数据顺序相关 RNG 和已完成的 epoch。阶段晋级从上一关卡末尾的状态继续。
- **逐次减半。** 每轮在相同累计 epoch 下比较验证目标。首版默认 `η=2`，下一轮计划人数为本轮计划人数除以 `η` 后向下取整，最少保留一个名额。实际晋级人数受完整验证成功的人数限制，分数相同按候选 ID 排序，全部候选失败时结束本轮。比如 8 个候选以 `1 → 2 → 4 → 8` epoch 晋级到 `8 → 4 → 2 → 1` 个，预算为 `8×1 + 4×1 + 2×2 + 1×4 = 20` 个实际增量训练 epoch。验证、读写 checkpoint 和训练都计入墙钟。
- **Hyperband。** 首版随机采样、单机顺序执行一轮括号集合，复用逐次减半的比较和晋级逻辑。记最小预算为 `m`、最大预算为 `R`，括号深度从 `s_max = floor(log_η(R/m))` 递减至 `0`。深度 `s` 的括号启动 `ceil((s_max+1) × η^s / (s+1))` 个候选，第 `i` 轮累计预算为 `floor(R / η^(s-i))`，其中 `i` 从 `0` 到 `s`。各括号结束预算为 `R`，深度为零的括号直接给予完整预算。局部、进化和贝叶斯搜索先继续用于固定预算路径，混合不同预算的反馈留待单独验证。 [Li 等，Hyperband 原论文，算法 1](https://jmlr.org/papers/volume18/16-558/16-558.pdf)
- **预算记账。** `--trials` 限制累计启动的新候选数，候选失败占名额，晋级沿用同一 ID。`--epochs` 定义单候选累计上限。新增总训练 epoch 上限时，以已开启的 epoch 记账，失败或中断的部分轮次也占用一份额度，并另报已完成 epoch、训练步数和墙钟。每次派发前检查剩余资源，墙钟到期后停止派发，尚未完成的轮次停止晋级。Hyperband 发现剩余候选名额不足以启动当前括号时，记录跳过原因并检查后续括号。报告记录完整的原计划与实际停止位置。
- **选优和重训。** 多阶段调度只用完成最大预算且在截止前取得有效验证的候选确定最终赢家。最大预算无有效结果时记录最高已完成预算的候选作为参考，并跳过自动重训。Anytime 曲线优先展示可用于最终选优的结果，各阶段较低预算的指标留在报告中。选出赢家后沿用训练集加验证集重训、外层测试只评一次的流程，重训时间单列。

### 首版范围与默认值

- CLI 拟保留 `--strategy`，增加 `--scheduler fixed|successive-halving|hyperband`，默认 `fixed`。早停独立开启。Python 端保留旧执行器协议，新增可选的分段能力接口。多阶段调度要求执行器明确支持该能力，不支持的组合在开跑前报错。
- MNIST CPU 的多阶段调度与早停先支持固定留出验证，多折场景继续走现有固定预算评估。车辆与 DonkeyCar 先验证小样本的逐关卡验证和续训，再跑全量。首版范围覆盖单次搜索内的候选晋级恢复，后续单独处理跨进程整场恢复及异步并行调度。

## 5. 审批项

1. 是否批准按五阶段推进，先在 MNIST CPU 和 CUDA 闭环验证，再接入车辆与 DonkeyCar。
2. 是否批准首版调度约定：按 epoch 分配资源，`η=2`，同步执行，逐次减半和 Hyperband 使用随机采样，只有完成最大预算的候选触发最终重训。
3. 是否批准故障处理范围：以候选故障隔离和可审计停止为主，默认零重试，跨进程恢复与异步调度后续另议。
