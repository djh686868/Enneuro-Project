## 一、背景与目标

本阶段（综设 III）任务池来自 `doc/综设III课件任务汇总.md`，共四类：

1. **核心主线**：CUDA C 算子实现与三方对比、单机多进程 PS 分布式训练模拟、GPU 资源监控与瓶颈分析、自动驾驶任务持续优化；
2. **进阶拓展**：ALL-Reduce、预训练模型库与迁移学习、框架深度优化；
3. **核心亮点**：MyFlows AutoPilot Agent 智能调优系统（六组件 + 5 个子 Agent + TPE 贝叶斯调参）；
4. **工程规范**：系统级测试（需制定测试计划）、可视化完善、最终报告，以及第 4/8/12 周三个汇报节点。

本文档的目标：把任务池对照项目现状裁剪成**可分配、可验收**的大模块 → 小任务，并给出设计思路、分工与测试计划。任务拆分的执行台账见配套明细表。

### 2.3 必须先扫清的拦路石（阻塞关系）

| 缺陷/欠账     | 内容                                                   | 阻塞谁                                |
| --------- | ---------------------------------------------------- | ---------------------------------- |
| **CR-1**  | `Optimizer._state` 为类变量、所有实例共享状态                     | M2 分布式（多 Worker 各建优化器会互相污染）        |
| **CR-2**  | Windows 多进程递归派生问题                                    | M2 Launcher（Windows 仅有 spawn 启动方式） |
| **HI-5**  | `FusedConvReLU.backward` 硬编码 `np.tensordot`，断 GPU 路径 | GPU 上使用融合算子训练（Agent 算子优化实验）        |
| **HI-13** | serving `Predictor.load_model` 为空壳（dummy 模型）         | 推理服务端到端测试                          |
| 测试基建      | 全部为脚本式测试、无 pytest/CI，各脚本手工 `sys.path.insert`         | 本学期"系统测试"要求的承重墙                    |
| 依赖清单      | `requirements.txt` 仅 numpy + opencv，与实际依赖严重不符        | 环境可复现性、CI                          |

**结论**：第 1–2 周全员优先完成测试基建与 CR-1/CR-2 修复，是所有主线任务的公共前置。

## 五、设计思路与关键技术决策

### 5.1 新增代码结构（尽量不侵入现有代码）

```
code/
├── eneuro/
│   ├── cuda_ops/        # M1：.cu 源码 + nvcc 编译脚本 + ctypes 绑定层 + RawKernel 原型
│   ├── dist/            # M2/M6：ps.py / worker.py / launcher.py / monitor.py / allreduce.py
│   ├── profiling/       # M3：nvml_sampler.py / step_profiler.py / analyzer.py
│   ├── agent/           # M4：planner / scheduler / executor / memory / critic / reporter / agents/
│   └── zoo/             # M5：预训练权重(npz) + 下载缓存
├── tools/
│   └── convert_weights.py   # M5：torch/paddle → eneuro 权重转换
└── tests/               # M7：pytest 化（conftest.py + unit/ + integration/ + e2e/）
```

### 5.2 各模块关键决策

1. **M1 CUDA 算子双轨交付**：先用 `cupy.RawKernel` 内联 CUDA 源码快速迭代（免编译系统、热加载），最终交付独立 `.cu` 文件、nvcc 编译成 dll、ctypes 加载——满足"底层算子 CUDA C/C++ 实现"的严谨性，且独立编译产物可被 Nsight 采集。正确性基准统一用 **NumPy fp64 参考**（而非 CuPy），误差阈值直接写成测试断言。
2. **M2 通信选 stdlib TCP socket** 而非 multiprocessing.Queue：能真实模拟网络、便于按方向计时（上传/拉取分离）、Windows 兼容性好；消息帧用 pickle/字节数组承载 ndarray。同步 BSP 先行，异步为选做。**单卡模拟多 Worker 时 GPU 上下文会争用**：扩展性实验用 LeNet/MNIST 小模型，写实性实验用自动驾驶模型，并在报告中说明单卡失真因素。
3. **M3 与 M4 的接口最早冻结**：M3 的 JSONL 监控数据 schema 是 Agent 的输入契约，第 1–2 周由 C、D 评审定稿，之后双方并行不再返工。计时埋点优先用现有 hooks 与 Trainer 回调，避免侵入训练主循环。
4. **M4 是"编排层"而非"重写层"**：五个子 Agent 只封装既有能力（ao/、Trainer、dist/、profiling/、zoo/、benchmark），Memory 用 SQLite 存实验记录，TPE 直接用 optuna（引入一个成熟依赖，好过自实现）。工程精力集中投在 Critic 闭环与异常回滚——这是 Agent "可信"的关键。
5. **M5 序列化格式分裂要显式管理**：ImageNet 权重走 npz 二进制（新增后端），框架 checkpoint 维持 JSON（兼容既有 Web 流程），转换工具同时产出并声明格式。
6. **M7 修复顺序以"解锁他人"排序**：CR-1/CR-2 最先（解锁 M2），HI-5 次之（解锁 GPU 融合训练），HI-13 与端到端测试配套。

### 5.3 风险清单与应对

| -- | -------------------------- | ---------------- | --------------------------------------------- |

## 七、系统测试计划

### 7.1 测试分层与准入标准

| 层级              | 范围            | 执行时机        | 关键用例与通过标准                                                                                                                                                        | Owner             |
| --------------- | ------------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| **L0 单元测试**     | 每个新算子/组件的核心路径 | 每次 PR 必跑    | ① CUDA 卷积 vs NumPy fp64：最大绝对误差 < 1e-3（fp32），池化输出精确一致 ② PS 聚合：mock 两 Worker 梯度求和/均值正确 ③ 冻结参数：backward 后无梯度、参数不变 ④ Critic：注入 NaN/爆炸 loss 100% 检出 ⑤ 数据划分器：无重叠、并集为全集 | 各模块 owner 编写，F 评审 |

### 7.2 测试流程约定

1. **PR 必须附带对应层级测试**，F 为测试评审人——落实"以测试结果驱动项目优化"；
2. **CI**（M7-06）每次提交跑 L0 + 冒烟，每晚跑 L2；
3. **缺陷 backlog 化**：62 项静态缺陷逐项修复后对应回归用例进 CI，做燃尽图；
4. **里程碑门禁**：第 4/8/12 周节点要求全量测试绿 + 端到端演示脚本一键复现；
5. **产物治理**：测试目录只留代码，权重 JSON、PNG、results/ 等产物全部 gitignore 并清理历史遗留。
