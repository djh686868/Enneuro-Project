# 一、CUDA 源文件
## 1. include
```c
#include <cuda_runtime.h>
#include <stdio.h>
```
## 2. CUDA算子
```c
__global__ void add_kernel(float *a, float *b, float *c, int n) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < n) {
        c[idx] = a[idx] + b[idx];
    }
}
```

## 3. 调用函数
```c
extern "C" __declspec(dllexport) 
void launch_add(float *a, float *b, float *c, int n) {
    float *d_a, *d_b, *d_c;
    size_t bytes = n * sizeof(float);

    cudaMalloc(&d_a, bytes);
    cudaMalloc(&d_b, bytes);
    cudaMalloc(&d_c, bytes);

    cudaMemcpy(d_a, a, bytes, cudaMemcpyHostToDevice);
    cudaMemcpy(d_b, b, bytes, cudaMemcpyHostToDevice);

    int threads = 256;
    int blocks = (n + threads - 1) / threads;
    add_kernel<<<blocks, threads>>>(d_a, d_b, d_c, n);

    cudaMemcpy(c, d_c, bytes, cudaMemcpyDeviceToHost);

    cudaFree(d_a);
    cudaFree(d_b);
    cudaFree(d_c);

    cudaError_t err = cudaDeviceSynchronize();
    if (err != cudaSuccess) {
        printf("CUDA Error: %s\n", cudaGetErrorString(err));
    }
}
```

# 二、编译

| 参数 | 全称/含义 | 作用 |
|------|-----------|------|
| `/EHsc` | Exception Handling, C++ style | 启用 C++ 异常处理。`s` 表示假定 `extern "C"` 函数不会抛异常，`c` 表示只捕获 C++ 异常。**如果没有这个选项，使用 `try/catch` 或标准库会报错。** |
| `/W3` | Warning level 3 | 设置警告级别为 3（默认是 `/W1`）。级别越高，警告越严格。`/W3` 是常用的“中等偏严”级别，`/W4` 更严格。 |
| `/nologo` | No logo | 编译时不打印版权横幅，让输出更干净。 |
| `/O2` | Optimize level 2 | 启用速度优化（级别 2）。这是发布版本的常用优化等级，会做内联、循环优化等。 |
| `/FS` | Force Synchronous PDB writes | 强制串行写入 PDB 调试文件。**当多个 `cl.exe` 进程并发写入同一个 PDB 时会用到**，`nvcc` 内部可能会并行调用编译器，所以加上它避免冲突。 |

# 五、基础算子一览

约定：**指针参数在前，标量参数在后**；所有输入/输出均为一维连续 `float32` 数组，长度 `n`。

| 源文件 | 导出函数 | 运算 |
|--------|----------|------|
| `vector_add.cu` | `launch_add(a, b, c, n)` | $c = a + b$ |
| `vector_sub.cu` | `launch_sub(a, b, c, n)` | $c = a - b$ |
| `vector_mul.cu` | `launch_mul(a, b, c, n)` | $c = a \times b$ |
| `vector_div.cu` | `launch_div(a, b, c, n)` | $c = a \div b$ |
| `vector_neg.cu` | `launch_neg(a, c, n)` | $c = -a$ |
| `vector_scale.cu` | `launch_scale(a, c, alpha, n)` | $c = a \times \alpha$ |
| `vector_add_scalar.cu` | `launch_add_scalar(a, c, beta, n)` | $c = a + \beta$ |
| `axpy.cu` | `launch_axpy(x, y, alpha, n)` | $y = \alpha x + y$（原地更新） |
| `vector_relu.cu` | `launch_relu(a, c, n)` | $c = \max(a, 0)$ |
| `vector_maximum.cu` | `launch_maximum(a, b, c, n)` | $c = \max(a, b)$ |
| `vector_minimum.cu` | `launch_minimum(a, b, c, n)` | $c = \min(a, b)$ |
| `vector_sum.cu` | `float launch_sum(a, n)` | 归约求和 |
| `vector_dot.cu` | `float launch_dot(a, b, n)` | 归约点积 |

## 归约算子说明

`vector_sum` / `vector_dot` 采用**两阶段归约**，返回值即计算结果：

1. 每个线程读一个元素（越界补 0）；
2. 块内用 `extern __shared__` 动态共享内存做折半（tree）归约；
3. 每个块只由 `tid == 0` 执行一次 `atomicAdd` 写入全局累加器，避免大量原子竞争。

对应 Python 侧需设置返回值类型：

```py
lib = ctypes.CDLL('./code/eneuro/cuda/dll/vector_sum.dll')
lib.launch_sum.argtypes = [ctypes.POINTER(ctypes.c_float), ctypes.c_int]
lib.launch_sum.restype = ctypes.c_float

total = lib.launch_sum(a.ctypes.data_as(ctypes.POINTER(ctypes.c_float)), n)
```

| 1e5 | sum | 0.3477 | 0.0196 | 0.0192 | 1 次拷贝 |

| — | 传输基线(H2D+D2H) | — | — | 0.154 / 1.643 / 15.85 | 2 次拷贝 |

## 结论

1. **当前 `CUDA(dll)` 是「拷贝受限」而非「算力受限」**：耗时 ≈ 传输字节数 ÷ 约 5 GB/s（PCIe 实测带宽）
   ＋ 约 0.25 ms 固定开销（`cudaMalloc/cudaFree` + kernel 启动 + 同步）。
   同一算子的耗时严格正比于拷贝次数：3 次拷贝（add/sub/mul/div/max/min/dot）> 2 次（neg/relu/scale）
   > 1 次（sum），与 n 无关。
2. 因此在这个朴素实现下，**CUDA(dll) 在 1e5 ~ 1e7 全部规模上都慢于 CPU numpy**
   （CPU/CUDA 比值 0.03x ~ 0.6x），比 cupy 常驻显存方案慢 30 ~ 100 倍。
3. 但 **kernel 本身极快**：n = 1e6 时 GPU 0.02 ms vs CPU 1.0 ms（≈ 50x），
   瓶颈完全在主机与设备之间的数据搬运。
4. 有个例外：`scale` / `add_scalar` / `axpy` 这类算子 CUDA(dll) 反而**快于 CPU 1.2 ~ 2.4 倍**——
   因为 EnNeuro 的 CPU 路径要为标量运算构建自动微分图（`Tensor + 标量` 会额外创建 Tensor）。
5. 优化方向：把接口从「每次调用都用主机指针」改为**显存常驻**（一次 `cudaMemcpy` 入，多次 kernel，
   最后一次拷回），或直接复用 cupy 的显存指针（`cupy.ndarray.data.ptr`），
   这样 CUDA 算子才能真正体现算力优势。

# 七、方案B：零拷贝 / 显存常驻接口

以 `vector_add.cu` 为样板，给算子增加一个「只借指针」的导出，旧接口原样保留作为回退：

```c
// 旧接口：主机指针，每次调用 malloc + H2D + kernel + D2H + free
ENE_EXPORT
void launch_add(float *a, float *b, float *c, int n);

// 方案B：设备指针，不分配不拷贝；stream 由调用方传入（传 0 即默认流）
ENE_EXPORT
void launch_add_dev(const float *d_a, const float *d_b, float *d_c, int n, void *stream);
```

## 四个必须处理的点

1. **同一个 primary context**：nvcc 的运行时 API 与 cupy 共用 primary context，因此 cupy 的
   `ndarray.data.ptr` 可以直接当设备指针用。前提是**同一张卡**，否则会写错显存或报
   `invalid device pointer`。
2. **stream 必须透传**：传 `cp.cuda.get_current_stream().ptr`。若 kernel 固定在默认流上启动，
   而 cupy 在非默认流里操作，两者无序 → 会读到旧数据。
3. **三项前置校验必须在 Python 侧做**：
   - `dtype == float32`：kernel 只按 `float` 解释内存，dtype 不对**不会报错，而是算出垃圾值**；
   - C 连续：非连续数组的 `.ptr` 只指向第一段，`size` 会骗人（修正要 `ascontiguousarray`，那是隐式拷贝）；
   - 同一设备。
4. **不同步**：把 `cudaDeviceSynchronize` 从算子里去掉，同步交给调用方，才能对齐 cupy 的异步流水线。

## 实测效果

`python code/tests/demo_cu_cupy_zerocopy.py`（n = 1e6，RTX 4060 Laptop，交错测量 min-of-7）：

| 调用方式 | 耗时 | 相对旧接口 |
|----------|------|-----------|
| `launch_add` 主机指针（malloc + 拷贝） | 2.4490 ms | 1.0x |
| `launch_add_dev` 设备指针（out 复用） | 0.0051 ms | **≈ 480x** |
| `launch_add_dev` 设备指针（每次 `empty_like`） | 0.0136 ms | ≈ 180x |
| `cupy` 自带 `a + b` | 0.0113 ms | ≈ 217x |

> 复用 out 时比 cupy 自带的 `a + b` 还快，原因是 `a + b` 每次都要在显存池里分配输出张量。
> 数据量小于 L2（本机 24MB）时结果还会进一步偏快。
>
> `out` 复用与每次分配差别不大，因为 cupy 显存池会复用已分配的块，不会真的反复 `cudaMalloc`。

## Python 侧调用骨架

```python
import ctypes
import cupy as cp

lib = ctypes.CDLL("./code/eneuro/cuda/dll/vector_add.dll")
lib.launch_add_dev.argtypes = [ctypes.c_void_p, ctypes.c_void_p,
                               ctypes.c_void_p, ctypes.c_int, ctypes.c_void_p]
lib.launch_add_dev.restype = None

def cuda_add(a, b, out=None, stream=None):
    if out is None:
        out = cp.empty_like(a)
    if stream is None:
        stream = cp.cuda.get_current_stream()
    # 前置校验：float32 / C 连续 / 同一设备（见 demo 中的 device_ptr）
    lib.launch_add_dev(ctypes.c_void_p(a.data.ptr), ctypes.c_void_p(b.data.ptr),
                       ctypes.c_void_p(out.data.ptr), out.size,
                       ctypes.c_void_p(stream.ptr))
    return out          # 不同步，与 cupy 语义一致
```

`eneuro.base.Tensor(device='cuda')` 的 `Tensor.data` 就是 `cupy.ndarray`，
所以 `Tensor` 可以直接作为算子输入：`cuda_add(ta, tb, tc)`。

## 归约算子的特殊处理

`sum` / `dot` 的结果是一个标量。若沿用「返回值」的形式，就必然有一次 D2H 拷贝，
零拷贝语义不成立。因此 dev 版改为**把结果写进调用方常驻的 1 元素显存缓冲**：

```c
// host 版：返回 float（内部含 D2H + 同步）
ENE_EXPORT float launch_sum(const float *a, int n);

// dev 版：结果写入常驻显存 d_out；清零用 cudaMemsetAsync 在同一条流上完成，不引起主机同步
ENE_EXPORT void launch_sum_dev(const float *a, int n, float *d_out, void *stream);
```

调用侧：

```python
d_out = cp.zeros(1, dtype=cp.float32)          # 常驻复用，不要每次新建
ops.dev("sum", ga, d_out=d_out)
cp.cuda.Stream.null.synchronize()
value = d_out.item()                            # 需要时才回主机
```

## 值得注意的三点

1. **逐元素算子全面优于 cupy 原生**（`cupy/dev` 约 1.1x）：cupy 的 `a + b` 每次都要在显存池里
   新建输出张量，而我们写进复用缓冲。`axpy` 领先最多（2.0x），因为 cupy 是
   `a * s` + `+ b` 两个 kernel 两次分配，我们是一个融合 kernel。
2. **归约算子慢于 cupy**（`sum` 0.51x、`dot` 0.75x）：我们的实现是「1 线程 1 元素 + 块内 256 宽
   折半 + 每块一次 atomicAdd」，cupy 用的是多级归约 + 向量化访存。要追平需要改成
   多元素/线程 + warp shuffle + grid 内二级归约。
3. **改造成本极低**：kernel 一行没改，只是把 `cudaMalloc/cudaMemcpy/cudaFree/cudaDeviceSynchronize`
   从导出函数里拿掉、加上 `stream` 参数。旧接口原样保留，可随时回退。

## 下一步：方案A（自管理显存常驻）

方案B 依赖 cupy 提供显存。若需要**不依赖 cupy**、或要自己控制 workspace 与显存上限，
可进一步实施方案A —— 但要先认清它的收益边界：

> **一次 H2D 只算一次的场景，方案A 相对 host 版几乎没有优势**（H2D 受 PCIe 带宽限制）。
> 它的价值在「一次进、多次算、一次出」的常驻复用。
